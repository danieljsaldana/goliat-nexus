01 / ARQUITECTURA COMPARTIDA

Una plataforma común.
Dos espacios para construir.

El hub reúne los servicios que Dev y Prod necesitan en común. Cada entorno conserva sus aplicaciones y sus datos. Así evitas duplicar infraestructura fija y puedes configurar la capacidad por separado.

SE CREA UNA VEZ

Hub & shared services

WAF para publicar webs y APIs, Firewall para controlar salidas, ACR para las imágenes y servicios de DNS, logs y estado Terraform.

EN CADA ENTORNO

Dev & Prod

Portales, APIs, Functions, Cosmos y secretos propios. Dos spokes sin peering directo, con acceso privado y permisos por identidad.

COSTE CON CONTEXTO

Menos duplicación.

Los servicios compartidos siguen generando coste aunque Dev escale a cero. El presupuesto envía avisos; la capacidad y la retención se ajustan en los tfvars.

03 / UNA APLICACIÓN PARA ENTENDERLO

De una solicitud
a una actividad.

Alba conecta dos portales, APIs privadas y una Function. Elige un caso y observa cómo se guarda la solicitud, se publica el evento y aparece la actividad.

Simulación local · No despliega ni conecta con Azure
01Frontend · Next.js

Next.js estático detrás del WAF compartido. Inicia sesión con Entra y PKCE y consulta las APIs por HTTPS, sin VPN. No recibe secretos de Cosmos.

02Backend · Node.js

El WAF dirige la petición al gateway Nginx privado y este a las APIs Node.js. Cada API verifica el token, el rol y el propietario antes de usar Cosmos y publicar el evento.

03Azure Functions · Node.js

Escucha Storage Queue y registra una actividad por solicitud, aunque reciba el evento varias veces. Un timer recupera los envíos pendientes del outbox.

SEGURIDAD EN CADA SALTO

Red privada.
Identidad en cada acceso.

Controles Zero Trust de red, identidad y acceso a datos. Estar conectado al hub no concede permiso sobre una API ni sobre otro entorno.

Leer el modelo de seguridad ↗
  1. 01

    Entrada WAF, orígenes cerrados

    El WAF inspecciona la entrada pública. Static Web Apps solo acepta su IP; el gateway interno solo acepta su subred. APIs y datos permanecen privados.

  2. 02

    Token y rol verificados

    Entra con PKCE; la API verifica audiencia, scope, rol, tenant y propietario.

  3. 03

    Acceso al secreto necesario

    Identidades administradas y permisos por secreto. Ninguna conexión Cosmos llega al frontend.

  4. 04

    Tu política corporativa

    Completa MFA, Conditional Access y PIM con tu organización. El producto no modifica esas políticas globales.

  3. 03 / DEVDespliega y verifica

    Publica imágenes, Functions y portales; comprueba el flujo.

  4. 04 / PRODAplica tu capacidad

    Mismo código, configuración y datos separados para Prod.

    Dominio Azure y certificado renovable; dominios propios opcionales.
